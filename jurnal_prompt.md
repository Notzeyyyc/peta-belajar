# Jurnal Prompt Terkurasi — Peta Belajar

## 1. Ide / PRD

Baca dan pahami `AGENTS.md`, `DESIGN.md`, serta seluruh dokumen acuan yang tersedia di repository. Bangun fondasi produk Peta Belajar untuk lomba MONE 2026 sesuai scope yang terkunci: input tujuan belajar, klarifikasi AI 2–3 pertanyaan berbasis chip, output AI tervalidasi Zod, lalu peta gap kompetensi dengan status kuasai/setengah/gap, persentase, indikator “kamu di sini”, “Mulai dari sini”, dan checklist progress yang mengubah peta secara live. Gunakan Next.js App Router (web) + Express (api) + TypeScript, Tailwind CSS, shadcn/ui, OpenAI SDK server-only, Drizzle ORM, dan better-sqlite3; jangan menambahkan fitur di luar scope. Sebelum coding, inspeksi struktur repository dan mockup di `design/`. Implementasikan slice end-to-end paling sederhana yang benar-benar bisa dijalankan, termasuk empty/loading/error state, validasi input, server-only LLM call, dan responsive UI 375px–1440px. Ikuti token visual `DESIGN.md` tanpa hardcode warna/radius baru. Tambahkan atau perbarui dokumentasi teknis yang diperlukan, tetapi jangan mengubah `DESIGN.md` tanpa izin. Jalankan lint, typecheck, dan test/build yang tersedia. Laporkan file yang berubah, keputusan penting, hasil verifikasi, serta blocker nyata tanpa mengarang hasil.

## 2. Debugging

Perbaiki bug pada implementasi Peta Belajar berdasarkan error, reproduksi, atau test failure yang tersedia di repository. Baca `AGENTS.md` dan `DESIGN.md` terlebih dahulu, lalu reproduksi masalah dengan perintah yang tepat sebelum mengubah kode. Telusuri akar masalah secara sistematis: boundary client/server, schema Zod dan `generateObject`, state klarifikasi, persistence Drizzle/better-sqlite3, validasi input, loading/error state, atau ketidaksesuaian visual. Terapkan perubahan terkecil yang menyelesaikan akar masalah; jangan menutupi bug dengan timeout, menghapus test, mematikan type checking, atau menambah dependency yang dilarang. Pertahankan scope produk dan token desain. Tambahkan regression test bila sesuai, jalankan test/lint/typecheck/build yang relevan, lalu verifikasi ulang skenario yang sebelumnya gagal. Laporkan reproduksi, akar penyebab, perubahan, dan output verifikasi yang benar-benar dijalankan.

## 3. Audit & Optimasi

Audit implementasi Peta Belajar secara menyeluruh tanpa menambah fitur baru. Periksa kesesuaian terhadap `AGENTS.md`, `DESIGN.md`, PRD, dan mockup: alur demo kurang dari 60 detik, UX mobile 375px dan desktop 1440px, aksesibilitas keyboard/focus/minimum hit target/non-color status, empty/loading/error state, motion dan reduced-motion, server-only API key, validasi trust boundary, keamanan magic link, query database, performa bundle, error handling, dan konsistensi status heatmap. Gunakan hasil inspeksi dan tool verifikasi nyata, bukan asumsi. Prioritaskan temuan berdasarkan dampak terhadap kelayakan lomba; perbaiki hanya masalah yang terverifikasi dan tetap dalam scope. Jangan mengubah token desain, menambah library terlarang, atau mengimplementasikan fitur Lapis 3. Setelah optimasi, jalankan lint, typecheck, test, build, dan bila tersedia pemeriksaan visual atau smoke test. Laporkan temuan sebelum/sesudah, perubahan yang dibuat, risiko yang tersisa, serta hasil verifikasi faktual.

## 4. Finishing

Siapkan Peta Belajar untuk dikumpulkan dan didemokan. Verifikasi checklist kelayakan satu per satu: dokumen acuan tersedia, repository siap, `PROMPT_LOG.md` dan `jurnal_prompt.md` lengkap, UI konsisten dengan tema pendidikan dan `DESIGN.md`, alur demo berjalan, deployment configuration siap untuk VPS standalone, API key tidak bocor ke client, database lokal berfungsi, serta semua layar memiliki empty/loading/error state. Jalankan pemeriksaan final yang relevan: lint, typecheck, test, production build, smoke test alur landing → tujuan → klarifikasi → peta → checklist → login/demo → persistence, dan scan secret/dependency bila tersedia. Perbaiki blocker yang ditemukan dengan perubahan minimal. Jangan membuat fitur baru, jangan mengganti stack, jangan mengubah `DESIGN.md` tanpa izin, dan jangan melakukan commit sebelum aturan waktu pada `AGENTS.md` mengizinkannya. Berikan hanya hasil yang sudah diverifikasi, daftar file final, perintah verifikasi beserta statusnya, dan blocker yang masih nyata.

## 5. Prompt Bebas

Berperan sebagai juri lomba MONE 2026 sekaligus pengguna siswa yang pertama kali mencoba Peta Belajar. Jalankan evaluasi berbasis bukti terhadap pengalaman dari landing page sampai peta gap selesai: apakah dalam kurang dari 60 detik tujuan produk terbaca, klarifikasi terasa ringan, peta memberi arah yang konkret, status kompetensi tidak ambigu, dan checklist benar-benar mengubah progress secara live? Catat friction paling kritis, bedakan bug dari opini desain, lalu usulkan perbaikan paling kecil dengan dampak terbesar yang tetap mematuhi `AGENTS.md`, `DESIGN.md`, dan scope fitur.
