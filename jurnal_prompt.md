Audit implementasi Peta Belajar secara menyeluruh tanpa menambah fitur baru. Periksa kesesuaian terhadap `AGENTS.md`, `DESIGN.md`, PRD, dan mockup: alur demo kurang dari 60 detik, UX mobile 375px dan desktop 1440px, aksesibilitas keyboard/focus/minimum hit target/non-color status, empty/loading/error state, motion dan reduced-motion, server-only API key, validasi trust boundary, keamanan magic link, query database, performa bundle, error handling, dan konsistensi status heatmap. Gunakan hasil inspeksi dan tool verifikasi nyata, bukan asumsi. Prioritaskan temuan berdasarkan dampak terhadap kelayakan lomba; perbaiki hanya masalah yang terverifikasi dan tetap dalam scope. Jangan mengubah token desain, menambah library terlarang, atau mengimplementasikan fitur Lapis 3. Laporkan temuan sebelum/sesudah, perubahan yang dibuat, risiko yang tersisa, serta hasil verifikasi faktual.

## 4. Finishing

Siapkan Peta Belajar untuk dikumpulkan dan didemokan. Verifikasi checklist kelayakan satu per satu: dokumen acuan tersedia, repository siap, `PROMPT_LOG.md` dan `jurnal_prompt.md` lengkap, UI konsisten dengan tema pendidikan dan `DESIGN.md`, alur demo berjalan, deployment configuration siap untuk VPS standalone, API key tidak bocor ke client, database lokal berfungsi, serta semua layar memiliki empty/loading/error state. Jalankan pemeriksaan final yang relevan: lint, typecheck, test, production build, smoke test alur landing → tujuan → klarifikasi → peta → checklist → login/demo → persistence, dan scan secret/dependency bila tersedia. Perbaiki blocker yang ditemukan dengan perubahan minimal. Jangan membuat fitur baru, jangan mengganti stack, jangan mengubah `DESIGN.md` tanpa izin, dan jangan melakukan commit sebelum aturan waktu pada `AGENTS.md` mengizinkannya. Berikan hanya hasil yang sudah diverifikasi, daftar file final, perintah verifikasi beserta statusnya, dan blocker yang masih nyata.

## 5. Prompt Bebas

Berperan sebagai juri lomba MONE 2026 sekaligus pengguna siswa yang pertama kali mencoba Peta Belajar. Jalankan evaluasi berbasis bukti terhadap pengalaman dari landing page sampai peta gap selesai: apakah dalam kurang dari 60 detik tujuan produk terbaca, klarifikasi terasa ringan, peta memberi arah yang konkret, status kompetensi tidak ambigu, dan checklist benar-benar mengubah progress secara live? Uji pada viewport mobile 375px dan desktop 1440px, termasuk keyboard, loading, error, dan kondisi data kosong. Catat friction paling kritis, bedakan bug dari opini desain, lalu usulkan perbaikan paling kecil dengan dampak terbesar yang tetap mematuhi `AGENTS.md`, `DESIGN.md`, dan scope fitur. Jika ada perbaikan yang aman dan jelas, implementasikan serta verifikasi dengan test/smoke test; jika tidak, jangan mengubah kode. Laporkan bukti pengamatan, prioritas, perubahan aktual, dan hasil verifikasi.
